# 채다 의견 피드 — 운영·로컬 API 연결

메시지와 메시지별 1단계 댓글을 한 페이지에서 작성한다. 제목·분류·처리 상태는 없다.
운영 웹은 `api.chaeda.kr`의 Community API에, 로컬 웹은 로컬 Community API에 연결한다.
예시 데이터로 되돌아가는 모의 동작은 사용하지 않는다.

## 실행

- 운영 웹: `https://chaeda.kr/feedback/`
- 운영 API: `https://api.chaeda.kr/community/feedback`
- 로컬 웹: `http://127.0.0.1:18766/feedback/`
- 로컬 API: `http://127.0.0.1:8300/feedback`
- 서버 실행·DB 적용·운영자 API: [Community README](../../backend/services/community-api/README.md#공개-의견-피드--로컬-연결)

운영에서는 Caddy의 `/community/feedback` 프록시와 `https://chaeda.kr` CORS 허용이 선행되어야 한다.

## 동작

- 별명은 선택이고 비워 두면 `익명`이다. 본문 1,000자, 별명 20자까지 입력한다.
- 메시지와 댓글은 API로 저장하며, 성공한 경우에만 입력란을 지운다. 연결 실패 시 초안을 유지하고 재시도할 수 있다.
- `더 보기`로 메시지를, 댓글의 `댓글 더 보기`로 다음 댓글을 조회한다. `새로 불러오기`로 다른 작성자의 새 내용을 확인한다.
- 같은 브라우저에서 쓴 글은 삭제할 수 있다. 댓글이 있는 원글 삭제는 같은 화면에서 확인한다.
- 작성자 확인용 무작위 토큰만 `localStorage`의 `feedback.client-token.v1`에 보관한다. 브라우저 데이터를 지우면 삭제 권한을 잃는다.
- 토큰 저장이 차단되면 삭제 권한을 잃지 않도록 작성 기능도 막고 안내한다. DB에는 토큰 해시만 저장한다.
- 운영자 메시지·댓글에는 닉네임 왼쪽에 `운영자` 뱃지를 표시한다. 서버가 응답한 `authorRole: "operator"`만 사용하며 별명만으로 부여하지 않는다.
- 운영자는 공개 작성 폼 대신 인증된 운영자 API를 직접 호출한다. 운영자 인증값은 웹에 넣지 않는다.
- 본문은 HTML로 실행하지 않고 텍스트로 표시한다. 개인정보를 입력하지 않도록 안내한다.
- 피드에서는 유입 측정·PostHog 스크립트를 불러오지 않는다. CSP는 운영 API와 로컬 API 연결만 허용한다.

## 직접 확인할 순서

1. 별명을 비우거나 입력해 메시지를 남긴다.
2. 댓글을 열고 댓글을 등록한다. 다른 메시지의 초안도 유지되는지 확인한다.
3. 새로고침 후 메시지·댓글과 `내 메시지`·삭제 버튼이 유지되는지 본다.
4. 운영자 API로 메시지와 댓글을 작성하고 새로 불러와 뱃지 위치를 확인한다.
5. 자기 댓글을 삭제하고, 댓글이 있는 자기 메시지의 삭제를 취소·확인해 본다.
6. API 연결이 끊어지면 오류와 재시도 안내가 나오고 초안은 유지되는지 본다.
